# Agent guide

1. Read `work/product.md` first to understand what speck is and its current state.
2. Read `docs/brief.md` for the full design: workflow, ticket size rules and the review loop protocol.
3. Work only from a `ready` ticket in `work/tickets/`. If no ticket exists for the change, create one or ask.
4. Keep changes within the ticket's size limits (`work/config.yml`). If the work is bigger, stop and propose a split.
5. Never merge. Never approve your own work. Review is done by the configured reviewer.

Use British English in docs.
