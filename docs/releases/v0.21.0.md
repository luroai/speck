0.21.0 makes Capture easier to work through and speck easier to leave running. Capture now counts its notes, lists notes from the same day in the order you captured them and lets you star the ones you like. You can turn `speck run` on from the command line, changes to the builder's settings apply from the next build without a restart, and a commit that would publish one of your private words under `speck/` is refused.

## What's new

- **Capture counts its notes.** The lane says how many notes it holds, such as "35 notes", as Build and Shipped do, so you can see at a glance how much is waiting to be shaped.
- **Same-day notes in the order you captured them.** New notes record the time as well as the day, and Capture lists notes from the same day latest first. Before, a day's notes came in file-name order, so the one you'd just captured could be anywhere in that day.
- **Star the notes you like.** Every note in Capture has a star. It's only a mark: the note doesn't move and nothing is committed. It's saved in the note, so it shows on your phone too.
- **`speck run --background`.** Turns `speck run` on from the command line, as the switch in Settings does, and waits until it's really watching before saying so. Setup now uses it, instead of starting `speck run` and guessing from its log whether it worked.
- **Builder settings apply without a restart.** Changing the builder, `builder_model`, its effort, its build or resume command, or how many builds run at once now applies from the next build, including builds `speck run` resumes or hands back. Before, they needed `speck run` restarted. Builds already running keep the settings they started with.
- **A ticket's full build log.** An open ticket in Build has a Full log button that opens its build log over the whole panel, like the Pipeline log, so a long build is easier to follow on a phone.
- **The builder's model in the facts.** A ticket's Builder fact names the model it builds on, such as "Claude · opus", when you've chosen one.
- **Reviewer tokens counted as each round saved them.** The panel's Reviewer tokens no longer count a resumed Codex conversation's earlier rounds again, leave out a Claude round's cached input, or show a Cursor round as nothing.
- **Private words kept out of every commit.** `speck init` now installs a check that refuses a commit adding one of your private words, or your home folder's path, to a file under `speck/`, naming the file and line but never the word. Before, only setting a ticket ready and shipping checked, so a note an agent committed straight to the main branch could slip through. `git commit --no-verify` skips it for one commit.
- **Setup asks fewer questions.** It leaves shipping, parallel builds and size limits at speck's defaults, with `auto_ship` off, and says you can change them later in Settings.
- **The panel behind a proxy.** The panel loads its lettering, styles and icons from addresses relative to the page, so they appear when a proxy serves it under a path.
- **Steadier tests.** Four of speck's own tests that failed now and then on a busy machine no longer do, so fewer finished tickets are sent back for nothing when they're tested before shipping.

Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v0.21.0 init
```

## Upgrading from 0.20.0

- Run `npx github:luroai/speck#v0.21.0 init` again in each project to update the speck command and skills. It keeps your config and tickets, and it's what installs the private-words check for commits.
- If your project already has its own pre-commit hook, or sets git's `core.hooksPath`, speck leaves it alone and says once that the check isn't installed.
- Notes captured before this release have no time on their `Captured:` line, so on a given day they're listed below the ones that do. Nothing needs changing in them.
- There are no new settings, so nothing needs adding to `speck/config.yml`.

See everything that's changed in the [0.21.0 section of the changelog](https://github.com/luroai/speck/blob/v0.21.0/CHANGELOG.md#0210--28-october-2026).
