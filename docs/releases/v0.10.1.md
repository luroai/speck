0.10.1 is a bug-fix release. It changes nothing you need to set up: it fixes one thing in 0.10.0, the panel asking you to ship a ticket by hand while `speck run` was already getting it shipped.

## What's fixed

- **Red means you're needed again.** When an automatic ship fails and `speck run` has handed the ticket back to its build, the ticket's row in the Build list no longer turns red or tells you to ship it from its review pack. It says the build is working on it, or, once the build has ended, that the ticket will be shipped again when main or its branch has a new commit. Before, a ticket could sit red through failed ships that `speck run` then sorted out by itself, so you couldn't tell from the colour whether you had anything to do. The row is still red, with the hint to ship it yourself, when `speck run` is off or no other ticket is on its way, as then nothing will ship it for you.
- **The failed ship's message stays on the row.** In each of these cases the row keeps the message from the ship that failed, so you can see why, including on a ticket that was blocked after its automatic ship failed. Before, a ticket blocked that way lost the message.

## Update

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.10.1 init
```

## Upgrading from 0.10.0

- Run `npx github:luroai/speck#v0.10.1 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- There are no new settings, so nothing needs adding to `speck/config.yml`, and `auto_ship` works as before.
- `speck status --json` has a new `handed_back` field on each ticket: when `speck run` last handed it back to its build after a ship it started, or null.
- A `speck run` that's already on keeps its old code until it switches by itself.

See everything that's changed in the [0.10.1 section of the changelog](https://github.com/luroai/speck/blob/v0.10.1/CHANGELOG.md#0101--20-october-2026).
