0.10.2 is a bug-fix release. It changes nothing you need to set up: it makes a build's log in the panel read the same whichever agent builds the ticket, so a Cursor or Codex build is as easy to follow as a Claude Code one.

## What's fixed

- **Times on Cursor build logs.** Each message and command in a Cursor build's log now starts with the time it happened, as a Claude Code build's does. Before, a Cursor build's log had no times, so you couldn't tell when anything happened or whether the build was stuck.
- **Times on Codex build logs.** Codex doesn't say when things happen, so speck now notes the time each line of a Codex build's log arrives, and shows it on each message, command and file change. Logs from Codex builds made before 0.10.2 still have no times.
- **Every step shows, under the same names.** A Cursor or Codex build's commands, file reads, edits, new files and searches show as `→ Bash`, `→ Read`, `→ Edit`, `→ Write`, `→ Grep` and `→ Glob`, as a Claude Code build's do. Before, a Cursor build's log showed only its messages and its commands, as `→ Shell`, and a Codex build's left out its file edits and sometimes showed its commands inside Codex's `/bin/bash -lc` wrapper.

## Update

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.10.2 init
```

## Upgrading from 0.10.1

- Run `npx github:luroai/speck#v0.10.2 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- There are no new settings, so nothing needs adding to `speck/config.yml`.
- If the `codex` command can't be found, a Codex build now starts and ends straight away with the reason in its log, rather than `speck run` saying it couldn't start the build.
- A `speck run` that's already on keeps its old code until it switches by itself, so the Codex builds it starts until then have no times.

See everything that's changed in the [0.10.2 section of the changelog](https://github.com/luroai/speck/blob/v0.10.2/CHANGELOG.md#0102--20-october-2026).
