speck is an agentic coding workflow that keeps your judgement in charge. You write small tickets and decide what's ready and what ships; one agent builds each ticket, a second, independent agent reviews it until it's right, and the whole record stays in your repo. 0.4.0 is about letting it run while you get on with something else: builds stop at approved, `speck run` ships what you've let it ship in one queue, every ship tests exactly what will land, and you can steer it all from the panel, on your phone as well as your computer.

## What matters most

- **One ship queue in `speck run`.** Builds now end once the reviewer approves. While `speck run` is on, it ships each approved ticket that `auto_ship` covers, one at a time, and tries again by itself once whatever stopped a ship has changed. When a ship needs work on the ticket, it hands the ticket back to its build to sort out and have reviewed again. Ships no longer race each other.
- **Ships test what will land.** `speck ship` tests the ticket merged with the latest base branch and lands exactly what it tested, so two tickets that each work alone but break each other are caught before they reach your base branch. A ticket that merges cleanly and passes ships without another review.
- **Steer it from the panel, anywhere.** Turn `speck run` on or off with the Auto-build switch, read an approved ticket's review pack and ship it with one button, and watch each build's stage as it happens. The panel fits a phone, can be added to your home screen as an app, and `speck panel --url <https address>` serves it through a private tunnel that makes you log in.
- **Review packs anyone can read.** Every approved ticket says in plain words what changed for someone using the product and how to see it, and `speck pack <id> --plain` prints a short review pack for deciding whether to ship without reading code.
- **Nothing waits for ever.** A stuck reviewer or a test run that stops making progress is ended with a plain message, a test that fails once by chance is run again before it fails a build or a ship (when `commands.test_files` is set), and a ship stopped partway no longer leaves the ticket stuck.

## Install

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.4.0 init
```

## Upgrading from 0.3.0

- Run `npx github:luroai/speck#v0.4.0 init` in your project to update the speck command and skills. It keeps your config and tickets.
- Only `speck run` ships auto-ship tickets now: a build stops at approved and no longer ships its own ticket. Keep `speck run` on (or switch on Auto-build in the panel) for tickets that `auto_ship` covers to ship. Otherwise they wait as approved until you turn it on or ship them yourself with `/speck-ship`.
- `speck ship` now runs the tests on the ticket merged with the latest base branch, so a ship after other tickets have shipped can take a little longer than before.
- Two new settings, both with defaults: `review_timeout_minutes` (30) and `test_stall_minutes` (5).
- Set `commands.test_files` in `speck/config.yml` (for example `node --test {files}`) if you haven't, so a failing test run gets its second try.
