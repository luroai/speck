1.6.1 is a patch release that keeps the line moving on a busy machine and finishes off the new Settings. Since 1.6.0, a ticket waiting on approved work that no longer fits main could stall, a test run queuing behind others could be cut off by a builder's command limit, and a fix ticket could list twenty tests when one really failed. This release fixes all three, fills the gaps left in Settings, tells you when the main checkout stops being a working checkout, and cuts down the duplicate notes builds leave in Capture.

## What's new

- **Waiting tickets don't stall on clashing work.** When a ticket waits for approved work that no longer merges cleanly into main, `speck run` waits for that ticket to ship and then starts it from main, and `speck status` and the panel say which ticket it's waiting for. So a ticket no longer sits stuck until you set it ready again.
- **Test runs step out of a long queue.** After 8 minutes waiting for a turn, `speck test` gives up its place and the build runs it again. So a busy machine doesn't stop a build partway because its agent's command limit cut off a test run.
- **Fix tickets name only real failures.** When the full suite's retry passes some of the tests that failed, the fix ticket and the panel's note name only those that failed again. So one real failure no longer turns into a fix ticket listing twenty.
- **The machine-wide build limit in Settings.** A "Builds at once on this machine" row sets `machine_parallel_builds` from the panel. So you can see and change the limit without the command line.
- **Swap the builder and the reviewer in one step.** Picking an agent for one that's the other's family asks whether to swap the other, and saves both at once. So you can switch Claude Code and Codex round without a detour through a third choice.
- **Settings for screen readers.** Each control is known by its plain name, such as "Name" or "Builder effort", rather than its key. So screen readers and voice control can find and read it.
- **A bare main checkout shows under Needs you.** When git's `core.bare` is switched on in the main checkout, `speck status`, the panel and All projects say so with the command that sets it back, and in pull request mode `speck run` holds merging without counting it against any ticket. So you hear about it straight away, and shipping carries on as soon as it's fixed.
- **Fewer, unrepeated notes in Capture.** Builds save a note only for something you'd notice or a test failing on main, and check the other builds running beside them first. So Capture isn't refilled with the same problem five times.

There are smaller fixes too: a tap on a closed Plan row's title on a touch screen opens the ticket rather than the tag under it, and several of speck's own tests are steady, one of which failed every build on newer versions of Node. The shipped price table has this release's rates. Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v1.6.1 init
```

## Upgrading from 1.6.0

- Run `npx github:luroai/speck#v1.6.1 init` again in each project to update the speck command and skills. It keeps your config and tickets, and nothing in `speck/config.yml` changes.
- `speck test` now exits with 19 when it has waited 8 minutes for a turn without running anything, and prints the command to run again. If you run it from your own scripts, run it again on that exit code.
- Swapping the builder and the reviewer between Claude Code and Codex no longer needs a step through a third choice: Settings offers the swap.

See everything that's changed in the [1.6.1 section of the changelog](https://github.com/luroai/speck/blob/v1.6.1/CHANGELOG.md#161--25-november-2026).
