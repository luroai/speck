0.11.0 is a minor release that adds document tasks. A ticket can now have its build write a document, such as an email, a plan or a report, instead of changing code. The document is reviewed against the ticket as carefully as code is, and it waits for you to read it before it ships, so speck's two gates work for writing as well as for code. You can also send any approved ticket back with a note saying what to change, rather than writing a new ticket.

## What's new

- **Document tasks.** A ticket with `task: document` and an `output:` folder, such as `output: emails`, has its build write a document from the sources the ticket names into that folder inside `outputs/`, rather than writing tests and code. Ask `/speck-ticket` for a ticket that writes a document and it sets both. `speck output <id>` prints the folder. The build only adds new files there or changes the ones the ticket names, never deleting or overwriting anything else. In the panel, such a ticket's card has a "document" tag.
- **A review that reads the document.** The reviewer is told where the document is and judges each criterion by reading it, quoting the passage it relies on, so you can see why it passed. Having no tests doesn't count against it.
- **The document at the top of its review pack.** A document task's review pack opens with a button for each file it wrote. A Markdown file opens formatted in the panel, and any other file in a new tab.
- **You ship documents yourself.** A document task never ships by itself, whatever `auto_ship` says: reading it is the review, so it waits for you. Shipping it runs no tests and files the ticket as done.
- **Ask for changes.** When you've read an approved result, code or document, and want something changed, the "Ask for changes" button in its review pack, or `speck changes <id> "<note>"`, sends your note back to the build that made it. The build makes the changes, the reviewer checks them against your note, and the ticket comes back approved before anything ships it.

## Update

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.11.0 init
```

## Upgrading from 0.10.3

- Run `npx github:luroai/speck#v0.11.0 init` again in each project to update the speck command and skills. It keeps your config and tickets, and adds `/outputs/` to the project's `.gitignore`, where document tasks write, unless a line there already ignores it.
- Existing tickets need no change: a ticket with no `task` counts as `task: code`. New tickets get a `task: code` line.
- There are no new settings in `speck/config.yml`. With `auto_ship` on, code tickets ship as before, but document tasks now wait for you.
- Ask for changes only works for a ticket that `speck run` built, since it hands your note to that build's session. The rounds that check your changes count towards `max_merge_rounds`, not `max_review_rounds`, and the ticket's history labels them merge rounds.
- A `speck run` that's already on keeps its old code until it switches by itself.

See everything that's changed in the [0.11.0 section of the changelog](https://github.com/luroai/speck/blob/v0.11.0/CHANGELOG.md#0110--21-october-2026).
