0.5.0 is a minor release in which a ticket gets one whole test run, when it ships, instead of several while it's built, and test runs no longer take over the computer: they take turns, at a lower priority than your own programs.
## What matters most

- **One whole test run per ticket, when it ships.** A build runs only the ticket's own test files, any existing ones it changed and those of any test that failed in its last run. `speck ship` runs the whole suite on the ticket as it would land, and hands the ticket back to its build if that breaks a test elsewhere.
- **A build starts without running the suite.** It lists the tests already failing from the result speck recorded for the same code (`speck test --recorded`), or writes `not checked` when there's none.
- **Test runs take turns and give way.** `speck test --files` waits its turn like a full run, and every test run speck starts runs through `nice`, when the system has it, so the computer stays usable while builds test.
- **No repeat runs of the same code.** A test run that waited its turn reuses the result another run recorded for the same code while it waited. A ship reuses only a passing result.
- **Builds don't stop partway.** The builder is told to wait for every test run and review round it starts, so a build started by `speck run` doesn't end early, leaving its ticket stuck as building.

## Install

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.5.0 init
```

## Upgrading from 0.4.0

- Run `npx github:luroai/speck#v0.5.0 init` in your project to update the speck command and skills. It keeps your config and tickets.
- The reviewer no longer sees a whole-suite run: it gets the output of the test files the build ran, and the whole suite runs in `speck ship`. A ticket that breaks a test elsewhere is now caught at ship rather than during its build.
- `speck test --files` waits its turn, sharing `max_parallel_tests` (1 unless you change it) with full runs, so a build's quick test runs can queue behind another build's full run.
- Set `commands.test_files` in `speck/config.yml` (for example `node --test {files}`) if you haven't: without it, `speck test --files` runs the whole suite.

See everything that's changed in the [0.5.0 section of the changelog](https://github.com/luroai/speck/blob/v0.5.0/CHANGELOG.md#050--15-october-2026).
