1.2.0 is the release where you set up your team. Settings opens on a card for each member, your engineering manager, the Builder, the Reviewer and QA, each with its own character, the agent it runs on and its bench: the agents that take over when its own runs out of usage. speck reads how much of each subscription you've used and shows it beside them. When an agent runs out, the work moves to the next one on the bench instead of waiting for the reset, so you set the team up once and speck keeps it working.

## What's new

- **Your team in Settings.** A card for each member shows its character, its job, the agent, model and effort it runs on and its bench, and you change them there. While a member's agent is limited, its card says so and names who stands in. So you can see who does what, and who takes over, in one place.
- **Each member has a bench.** `builder_bench`, `reviewer_bench` and `watch_bench` list the agents, in order, that each member switches to while its own agent is limited. So one agent running out no longer stops the line.
- **Builds carry on on another agent.** While the builder's agent is limited, new builds start on the next free agent on its bench. A build that stops partway with its limit more than an hour from resetting is handed to the next one too, on the same branch, told to read what's been done so far. So a limit hours from resetting doesn't hold up the queue.
- **Reviews carry on on another agent.** While the reviewer's agent is limited, each round runs on the next agent on its bench that's free and allowed to review the build, and the review pack says so. Builds don't sit waiting at their next round.
- **QA is a team member of its own.** Checks in the running app can run on their own agent, model and effort with `qa_agent`, `qa_model`, `qa_effort` and `qa_bench`, and say QA checked them. So clicking through an app can use a different model from the one that decides what to do about a stop.
- **Your subscriptions' usage.** `speck agents` and Settings show how much of each window Claude Code, Codex and Cursor have used and when each resets, with a bar that turns orange at 90%. So you can see a limit coming before work stops on it.
- **Codex and Cursor limits are waited out.** A Codex or Cursor build that stops on its usage limit is carried on after the reset, as a Claude build already was, and `speck status` says which agent is limited and until when.

## What's changed

- **A failing full suite has a row of its own** under Needs you in Build, naming the commit and how many tests fail, with a view listing them. So the Needs you count always matches something you can see.
- **Two trackpad swipes change lane twice**, even straight after each other, as in Cursor's browser pane.

The shipped price table has this release's rates. Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v1.2.0 init
```

## Upgrading from 1.1.0

- Run `npx github:luroai/speck#v1.2.0 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- The benches start blank, and a blank bench means your agents in the order `speck agents` lists them, without the member's own agent and without any model provider on an API key, as those bill per token. So with Codex or Cursor installed and signed in, work now moves to them while Claude is limited, where 1.1.0 waited. To choose who stands in, set a bench, for example `speck config set builder_bench "codex"`. Benches are kept for your machine only, and speck refuses one naming an agent it doesn't know or the member's own agent.
- The watch agent's stand-in now comes from `watch_bench`. A blank one leaves out model providers on an API key, which 1.1.0 could take: to keep one, name it on `watch_bench`.
- QA's settings start blank, and then app checks run as in 1.1.0, on the watch agent. Set `qa_agent` to give them an agent of their own; `qa_model` and `qa_effort` blank use that agent's defaults.
- Cursor's usage is read from its own usage screen: speck opens Cursor's agent in an empty folder of its own, shows `/usage` and closes it, so no model runs. It does this only when the last reading is more than 10 minutes old or after a Cursor run speck started, and needs the system's `script` command. It has been checked on Linux, not yet on a Mac. Claude Code's and Codex's usage is read from their own runs, so an agent speck hasn't run yet has no reading.

See everything that's changed in the [1.2.0 section of the changelog](https://github.com/luroai/speck/blob/v1.2.0/CHANGELOG.md#120--11-november-2026).
