0.9.1 is a bug-fix release. It changes nothing you need to set up: it fixes seven things in 0.9.0 that got in the way of setting speck up, building, shipping through pull requests and seeing where things stand.

## What's fixed

- **The right test command for pnpm, yarn and bun.** `speck detect`, which setup reads, now suggests `pnpm test`, `yarn test` or `bun run test` for a project that uses that package manager, instead of always `npm test`, and the install command it suggests names the same one. Before, setup offered a test command the project didn't use, and you had to correct it.
- **Tickets keep their builder after you switch back to Claude Code.** With `build_command` set to speck's own command for Claude Code, a ticket made with Codex or Cursor is still built by Codex or Cursor, as the Settings view promises. Before, switching back to Claude Code meant Claude Code built them all.
- **A pull request that clashes on GitHub goes back to its build.** With `ship_mode: pr`, when GitHub says a ticket's pull request conflicts with the main branch, `speck run` hands it back to its build to bring in the newer work and be reviewed again. Before, an auto-shipped ticket sat approved with the conflict until someone noticed.
- **A ticket set ready again is built again.** When a build stops before it has started its ticket, `speck run` starts it again as soon as you set it ready again, or commit a change to it, and that's on the main branch. Before, `speck run` had to be restarted first.
- **An idea count that leaves out dropped ideas.** The `IDEAS` line in `speck status` counts ideas waiting, inbox notes and ticketed ideas apart, and no longer counts ideas triage has dropped, so it shows what's really left to shape and matches the panel's Ideas and Inbox tabs.
- **The Foreman's questions say what became of them.** In `speck status` and the Foreman's detail, a question the Foreman asked says whether you answered it, dismissed it or it no longer waits for you. Before, a question you'd dealt with still read as if it were waiting.
- **Keyboard focus comes back to where you were.** Closing a ticket's full view in the panel puts the focus back on its Full ticket button, so someone using the keyboard doesn't have to Tab from the top of the page.

## Update

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.9.1 init
```

## Upgrading from 0.9.0

- Run `npx github:luroai/speck#v0.9.1 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- There are no new settings, so nothing needs adding to `speck/config.yml`.
- With `build_command` set to speck's own command for Claude Code, a ready ticket whose `builder:` is Codex or Cursor is now built by that agent, which must be installed on this machine. A `build_command` you've written yourself is still used for every ticket.
- The `IDEAS` line in `speck status` now reads `IDEAS (<total>: <n> waiting, <n> in the inbox, <n> ticketed)`, and its total leaves out dropped ideas. `speck status --json` has a new `idea_counts` field with the same counts. Anything that reads the old line may need updating.
- With `ship_mode: pr`, once a ticket handed back for a conflict is approved again, the next ship asks you to run `speck pr` for it.
- A `speck run` that's already on keeps its old code until it switches by itself.

See everything that's changed in the [0.9.1 section of the changelog](https://github.com/luroai/speck/blob/v0.9.1/CHANGELOG.md#091--19-october-2026).
