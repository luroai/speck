0.10.0 makes speck work entirely in Cursor. Pick Cursor as the builder during setup and it offers to set up everything else on Cursor too: builds, reviews on a model you choose from your own account, and the Foreman. It takes setup's questions alone, with no hand edits to `speck/config.yml`.

## What's new

- **An all-Cursor setup in one question.** When you pick Cursor as the builder, setup offers builds on Cursor's `auto`, a Cursor reviewer on a model you pick and the Foreman on Cursor or another agent you have, and makes each setting with `speck config set`. Before, a working Cursor setup took a hand-written reviewer command, `allow_same_model_review` and model names the agent had to guess.
- **Models from your own account, never guessed.** Setup offers only the models `speck agents --json` lists for your account. When the agent's chat walls off the network, as Cursor's does, it reads them again outside that sandbox, or asks you to paste the list from `agent models` in your own terminal. Before, the agent could make up a model name that didn't exist.
- **A Cursor reviewer with no command of your own.** Set `reviewer: cursor` and speck runs Cursor's CLI for you, read-only, on `reviewer_model`, carrying on the same chat each round. It passes `--trust`, so a review no longer stops at Cursor's Workspace Trust prompt with nobody there to answer it.
- **Cursor reviewing Cursor without switching the check off.** A Cursor build reviewed by Cursor on a model of its own now passes the same-model check, so you no longer turn on `allow_same_model_review` for the whole project. It's still refused when both run the same model, when the reviewer's model is blank or `auto`, or when `build_command` is set.
- **The Foreman on Cursor.** Set `foreman` to `cursor`, or leave it blank with Cursor as the builder, and the Foreman runs on Cursor, on `foreman_model` when it's set. Before, someone with only Cursor couldn't use the Foreman at all.
- **Tickets can ship in a folder with no tests.** In a folder without tests, such as one of documents, setup recommends `node --test` as `commands.test` instead of leaving it blank. It passes until there are tests and runs the ones later tickets add. Before, `speck ship` refused every ticket there, as it needs a test command that passes.

## Update

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.10.0 init
```

## Upgrading from 0.9.1

- Run `npx github:luroai/speck#v0.10.0 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- There are no new settings. `foreman` now takes `cursor` as well as `claude` and `codex`.
- With `foreman` blank and `builder: cursor`, the Foreman now runs on Cursor rather than Claude Code. Set `foreman` to `claude` to keep it on Claude Code.
- A `reviewer_options.cursor.command` you've written is still used. You can remove it to let speck run Cursor itself, or add `--trust` to it so a review doesn't stop at Cursor's Workspace Trust prompt.
- With Cursor as both builder and reviewer, `build_command` blank and a `reviewer_model` other than `auto` and the builder's model, you can set `allow_same_model_review` back to false.
- The Settings view doesn't offer Cursor as the reviewer yet, unless you have a `reviewer_options.cursor` command: set it with `speck config set reviewer cursor`.
- A `speck run` that's already on keeps its old code until it switches by itself.

See everything that's changed in the [0.10.0 section of the changelog](https://github.com/luroai/speck/blob/v0.10.0/CHANGELOG.md#0100--20-october-2026).
