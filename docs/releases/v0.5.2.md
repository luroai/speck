0.5.2 is a patch release that cuts needless stops in builds and ships: tickets that are nearly done carry on by themselves instead of waiting for you, and a ship refused for failing tests points at both of the places the failure may come from.

## What matters most

- **A re-review after an approval doesn't use up review rounds.** When an approved ticket's ship is refused and it needs a small fix to its own code, its re-review gets rounds of its own, as a re-review after a merge already did. A ticket approved in its last allowed round no longer stops for a tiny fix. Such rounds show as a merge round in its review history, even when nothing was merged.
- **One finding from approval gets one extra round.** A ticket that reaches the review round limit with no more than one blocking finding left gets an extra round by itself, instead of stopping to ask you. If that round doesn't approve it, it stops as before. Its review pack names the extra round.
- **A refused ship names both possible causes.** When the tests fail on a ticket as it would land while the base branch's own tests pass, the message says the failure may come from the ticket's own change, or from it together with the base branch's newer changes, so the build that picks it up checks both.
- **`speck run`'s Claude Code builds can't run commands in the background.** A build can no longer leave a test run or review round running and end its turn, which stopped the build partway with its ticket stuck as building or reviewing.
- **A test that failed by chance doesn't any more.** A check in speck's own suite that failed when the clock ticked over a second gives the same result every time, so it no longer costs a second test run or hands an approved ticket back.

## Install

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.5.2 init
```

## Upgrading from 0.5.1

- Run `npx github:luroai/speck#v0.5.2 init` in your project to update the speck command and skills. It keeps your config and tickets.
- Nothing in `speck/config.yml` needs changing. You no longer need to raise `limits.max_review_rounds` to let a ticket that's one finding from approval finish.
- If you set `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` yourself where you start `speck run`, speck keeps your value instead of setting it to `1`, so builds then follow your setting.

See everything that's changed in the [0.5.2 section of the changelog](https://github.com/luroai/speck/blob/v0.5.2/CHANGELOG.md#052--16-october-2026).
