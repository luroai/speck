0.21.1 is a bug-fix release, with a friendlier review pack for tasks. It changes nothing you need to set up: the panel's switch no longer leaves a `speck run` behind when it times out, a failed Codex review says why, the review pack's reviewer tokens match the panel's, and a task's review pack opens with a summary and folds its subfolders.

## What's fixed

- **The switch cleans up after a time-out.** If the panel's switch turns `speck run` on and it doesn't start watching within 10 seconds, the panel now stops it before showing the error. Before, it was left running and could start building a moment later while the switch showed it off. `speck run --background` behaves as before.
- **Private words handed back in pull request mode.** When `speck run` can't merge a ticket because its speck files hold one of your private words or your home folder's path, the ticket now goes back to its build to take them out, as it already did when shipping locally. Before, it waited for you.
- **Codex says why a review failed.** A Codex review round that fails now gives Codex's own reason, such as a usage limit and when it resets. Before, the message stopped after "codex exited 1:", so you couldn't tell a usage limit from a broken setup.
- **One reviewer tokens figure.** The review pack's and the Delivery log's Reviewer tokens now match the panel's for the same ticket. Before, a resumed Codex review or a Claude review could show a very different number in the pack.
- **Quicker end to every build.** When a build ends, speck reads only the Codex sessions that changed since the ticket's first build started, rather than every session Codex ever saved, so the end of a build no longer slows down as Codex's history grows. The spend it counts is the same.
- **Steadier tests.** More of speck's own tests that failed now and then on a busy machine no longer do, so fewer finished tickets are handed back at ship for a failure they didn't cause. One check that had stopped checking anything works again.

## What's changed for tasks

- **Start here.** A task's build now writes a `summary.md` at the top of its output folder, saying what it found or made and which files to read. The task's review pack opens with it, with Ship straight under it, so you no longer scroll past every file to ship.
- **Folded subfolders.** A task's review pack names its files from inside its output folder and folds each subfolder into one row, such as `imports/ · 48 files`, that you press to open. A task that leaves dozens of files no longer fills the pack with buttons.

Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v0.21.1 init
```

## Upgrading from 0.21.0

- Run `npx github:luroai/speck#v0.21.1 init` again in each project to update the speck command and skills. It keeps your config and tickets, and it's what gives a task's build the step that writes its summary.
- Tasks built before this release have no summary, so their review packs list every file above Ship, as before.
- Tickets already shipped keep the Reviewer tokens figure they were given at the time.
- There are no new settings, so nothing needs adding to `speck/config.yml`.

See everything that's changed in the [0.21.1 section of the changelog](https://github.com/luroai/speck/blob/v0.21.1/CHANGELOG.md#0211--29-october-2026).
