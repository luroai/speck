0.5.4 is a patch release so that every install command gets the newest release, agents set a ticket ready only when you tell them to, and the README says plainly what speck is and who it's for.

## What matters most

- **Every install command gets the newest release.** Before, the README's setup prompt named a fixed release that had to be updated by hand at each release, so it fell behind whenever that step was missed, and other install commands named no release at all, so they installed whatever was on `main` at the time. Now the setup prompt, the README's "Without an agent" section, the brief, `/speck-setup` and the message from a copy of speck that can't install itself all install the newest release. The command is in single quotes, so it works the same in zsh, the default shell on a Mac, as in bash. Until a new release has been tagged, they install the release before it.
- **Agents set a ticket ready only when your latest message says to.** Setting a ticket ready is your decision, and with `speck run` on and auto-ship covering it, a ticket set ready by mistake could ship without you seeing it. Every speck skill that can set a ticket ready now says that an agent does so only when your latest message tells it to set that ticket ready: picking an option, approving wording, answering a question or agreeing to a plan doesn't count. Fix tickets for a broken base branch are still set ready by the build that finds the failure. This is guidance to the agent, not a lock: the panel and `speck set` still let you set a ticket ready.
- **The README says plainly what speck is.** It has a new tagline, "Ship code you can't read, and still trust it.", also in `speck help` and the package description. It opens by saying who speck is for, what you do and why you can trust the result, shows a picture of an agent conversation beside speck's panel, and tells the landing page's story with the setup prompt straight after it. A new "Under the hood" section gives the technical detail, and each section starts with one plain sentence saying what it's for.

## Install

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.5.4 init
```

## Upgrading from 0.5.3

- Run `npx github:luroai/speck#v0.5.4 init` in your project to update the speck command and skills. It keeps your config and tickets, and adds the rule about setting tickets ready to your project's agent guide.
- Nothing in `speck/config.yml` needs changing.

See everything that's changed in the [0.5.4 section of the changelog](https://github.com/luroai/speck/blob/v0.5.4/CHANGELOG.md#054--16-october-2026).
