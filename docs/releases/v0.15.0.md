0.15.0 is a minor release that rebuilds the panel round speck itself. What used to be called the Foreman is now just speck, living on a little LCD screen at the top of the panel, where it acts out what the pipeline is doing so you can tell at a glance whether it's building, waiting or needs you. Under it, Plan, Build and Shipped are cards you swipe between, each ticket is two short lines until you open it, and the panel takes Cursor's look, so it fits a phone or a narrow side pane beside your editor. Settings now sets up your agents and any API provider, and builds catch broken tests before their first review.

## What's new

- **speck's screen.** The panel's header is speck's LCD screen, with the pipeline's status, the time, and speck reacting to each build, ship and question with a short animation and a caption. When something needs you, its frame turns red.
- **The Pipeline log.** Press the screen to open the Pipeline log: what `speck run` has been doing, as a terminal of short, timed lines, newest at the bottom.
- **Lanes you swipe between.** Plan, Build and Shipped are cards side by side, in one column at every width. Swipe, use the arrow keys or tap a lane's name in the strip under the screen. Shipped now lists the latest ten tickets.
- **Shorter tickets.** A closed ticket is two short lines that say what it's doing in words. Open it to see its steps as a coloured track, its facts in a small table and its dependencies in a box. A ticket waiting for you to ship it is green, and one that needs you is red. A build's log looks like a terminal.
- **The full ticket as a document.** The full ticket and a review pack open over the whole panel and read like a document, with the same steps and facts as the open card.
- **Cursor's look.** The panel uses Cursor's colours, fonts and rounded corners, with System, Light and Dark appearances.
- **Your agents and any API provider.** Settings has a Your agents group: add or remove the agents you use on this machine, or add any Anthropic-style API provider with its address, key and models. Each role picks from one list of your agents' models, and the builder has an effort setting of its own. `speck agents` does the same from the command line.
- **Builds catch more before review.** Before its first review, a build runs the existing tests that name a file it changed, so a change that breaks an older test is fixed before review rather than at shipping. When you shape tickets, speck chains them only when they change the same part of a file, so more build side by side.
- **Tasks.** A ticket that does a job rather than changing code, such as drafting an email, is now called a task, with `kind: task`.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v0.15.0 init
```

## Upgrading from 0.14.0

- Run `npx github:luroai/speck#v0.15.0 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- The Foreman's settings are now `watch`, `watch_agent`, `watch_model` and `watch_effort`, in place of `foreman_fixing`, `foreman`, `foreman_model` and `foreman_effort`. The old names still work, and your config is rewritten only when you change one of them.
- Answer speck's questions with `speck answer` and `speck dismiss`. The old `speck foreman answer` and `speck foreman dismiss` still work.
- New tickets say `kind: code` or `kind: task`. Tickets that say `task: document` keep working as tasks, and speck never rewrites them.
- Settings' API keys box is gone: a provider's key is now entered in Your agents. If you already use DeepSeek, nothing changes.
- The Pipeline pop-up no longer has its Right now list: run `speck status` to see why a ready ticket isn't building.
- A shipped ticket's status can no longer be changed.

See everything that's changed in the [0.15.0 section of the changelog](https://github.com/luroai/speck/blob/v0.15.0/CHANGELOG.md#0150--25-october-2026).
