0.9.0 is a minor release that gives the panel the look of the speck design, a dot-matrix LCD screen, lets you answer the Foreman's questions and see what it will do, builds each ticket with the agent it was made for, and ships through pull requests to a main branch that only takes them.

## What matters most

- **A panel that looks like speck.** The builder badges, the Foreman's builder, the header's logo and title and the app icons now follow the speck design: speck on a small green dot-matrix screen. A builder hops and blinks into its new pose when its ticket moves on, so you can see work moving at a glance. A badge waiting for you has a purple frame and a blocked one a crimson frame. The lettering comes with speck, so it looks the same with no internet connection.
- **See what the Foreman will do, and answer it.** With Fixing set to `fix`, the header says "Fixing on", and each blocked ticket says whether the Foreman will take its recommendation or is waiting for you. Once one is taken, the ticket says who took it, which option and when. When the Foreman agent asks you a question about a stuck ticket, you can answer or dismiss it on the ticket's card, in the Foreman's detail, or with `speck foreman answer <id> "<text>"` and `speck foreman dismiss <id>`. Before, its question just waited.
- **Each ticket built by the agent it was made for.** With `build_command` blank, `speck run` builds each ticket with the builder its `builder:` field names, so switching the builder no longer changes who builds tickets already written. A ticket whose builder isn't installed isn't started, and the Foreman's detail says why.
- **Switching builders doesn't leave a model behind.** Switching the builder clears `builder_model` when the new builder doesn't offer it, and tells you, so Codex builds aren't started with a model left over from Claude Code. A Codex builder and reviewer on different models are now accepted without `allow_same_model_review`, as a Claude Code pair already was.
- **Pull request mode works on a protected main branch.** With `ship_mode: pr`, the ticket's move to done goes through its pull request, so speck never pushes straight to your main branch. A main branch that only takes pull requests, the main reason to use pull request mode, now works. Setup offers pull request mode when your main branch needs it.
- **A reviewer that can only read the code.** The built-in Claude reviewer no longer loads your MCP servers or claude.ai connectors, such as Gmail or Google Drive.
- **One `speck run` per repo, always.** Starting a second one is refused with a message naming the one that's running, even after it has switched to new code, and turning it off in Settings waits until all of it has stopped. Two at once could start the same build or ship twice. `speck run` also no longer says its own builds are "being built outside speck run".
- **Setup finds Cursor under its new name.** `speck detect` finds Cursor's command-line tool as `agent` or `cursor-agent`.

## Install

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.9.0 init
```

## Upgrading from 0.8.0

- Run `npx github:luroai/speck#v0.9.0 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- There are no new settings, so nothing needs adding to `speck/config.yml`.
- With `build_command` blank, a ready ticket whose `builder:` names a different agent from the one in `speck/config.yml` is now built by that agent, without `builder_model`. If that agent isn't installed on this machine, the ticket waits and the Foreman's detail says why. With `build_command` set, as Claude Code is set up, nothing changes.
- With `ship_mode: pr`, a pull request opened before you upgrade gets the ticket's move to done added the first time you ship it, and is merged on a later try once GitHub has run its checks.
- A `speck run` that's already on keeps its old code until it switches by itself.
- A browser or phone may keep showing the old icon until it clears its stored copy.

See everything that's changed in the [0.9.0 section of the changelog](https://github.com/luroai/speck/blob/v0.9.0/CHANGELOG.md#090--19-october-2026).
