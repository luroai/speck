1.1.0 is the release where speck checks the work. When a build needs something checked in the running app, such as how a page looks or that signing in works, speck no longer has to stop and ask you. It works out how to start your app, starts it from the ticket's copy of the code, signs in with a test login kept on your machine, looks for itself and carries on, or asks you, saying what it saw. Its screenshots are in the review pack, so you can see what it looked at before anything ships.

## What's new

- **speck checks a build's question in the running app.** A build asks for a check in the app with a `Check in the app:` line on its question. With `watch: decide`, or `watch: fix` when the check clearly passes, speck does the check itself on a low-risk ticket and goes with the build's recommendation when what it saw agrees. So questions about how something looks stop waiting for you, and you still see the evidence.
- **speck starts your app.** `speck app <id>` starts it from a ticket's copy of the code on a free port and prints the address, and `speck app <id> --stop` stops it and only it. Tell speck how with `commands.start`, or leave it blank: the first time it needs the app, speck works the command out from the project, tries it and saves the one that works.
- **Test logins on your machine.** `speck logins set <name>` keeps a username and password for testing your app, out of git and readable only by you. A commit or ship that would publish a saved password is refused, and review rounds show it as `[private]`.
- **It carries on after usage limits.** When Claude's or the reviewer's usage limit stops a build, speck waits until the limit resets and resumes it by itself, instead of leaving it for you. The watch agent can book a resume for the time a limit resets, and while Claude is limited it does its looks on another of your agents.
- **Ships wait only for your quick tests.** Set `commands.test_full` to your full suite, and `speck run` runs it on the base branch after ships, telling you under Needs you if it fails, while each ship waits only for `commands.test`. A build's list of tests already failing covers the full suite when it can.

## What's changed

- **Auto-ship trusts only speck's own review runs.** A ticket ships by itself only when its approving round was recorded by speck's own run of the reviewer and hasn't changed since, checked against a receipt kept outside the ticket's branch. Anything else waits for you at Ship, saying why, so a builder can't get its own approval shipped by itself.
- **Private words are checked everywhere.** The commit check now covers every file a commit changes and the commit message, not only `speck/`. A reviewer quoting a private word no longer stops a ship: speck writes it as `[private]` in the saved round.
- **A ticket's facts as tiles** in its full view, like Shipped's figures.
- **The README describes speck as of 1.1.**

The shipped price table has this release's rates. Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v1.1.0 init
```

## Upgrading from 1.0.0

- Run `npx github:luroai/speck#v1.1.0 init` again in each project to update the speck command and skills. It keeps your config and tickets. It also adds the new commit message check beside the existing one, and `speck doctor` shows a line for each.
- For speck to check questions in your app, set `commands.start` to the command that starts it, with `{port}` where the port goes, using `speck config set commands.start "<command>"`, and `app_url` if it isn't served at `http://127.0.0.1:{port}/`. Or leave it blank, and with `watch` at `fix` or `decide` speck works it out the first time it needs it and commits it to `speck/config.yml`.
- If your app needs signing in, save a test login with `speck logins set <name>`. Use a password that isn't an everyday word: a saved password refuses any commit that holds it.
- To have ships wait only for quick tests, point `commands.test` at them and set `commands.test_full` to your whole suite. Leave `commands.test_full` blank and nothing changes.
- A round saved with `speck record` no longer ships by itself: it waits for you at Ship. That includes every round from the `claude-subagent` reviewer. Tickets approved before you update have no receipts either, so each waits for you at Ship once.
- Builds now ask for checks in the running app only as a blocked question with a `Check in the app:` line, which the new skills say how to write.

See everything that's changed in the [1.1.0 section of the changelog](https://github.com/luroai/speck/blob/v1.1.0/CHANGELOG.md#110--11-november-2026).
