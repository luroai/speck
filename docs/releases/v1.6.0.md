1.6.0 is a minor release that makes the panel look and work like part of Cursor. Settings had grown into a long form with ⓘ buttons and a Save button at the bottom. Now it reads like Cursor's own settings, with plain names, switches and compact menus, and it saves each change as you make it. The release also lets you try an approved ticket's app before you ship it, caps builds across every project on your machine, warns on the bridge when an agent nears its usage limit, and stops tickets built on others from stalling.

## What's new

- **Settings laid out like Cursor's.** Each setting has a plain name with a short line saying what it does, grouped on soft blocks, with switches for on and off and compact menus. Press a setting's name to read its full explanation. So Settings is quick to scan and sits naturally beside Cursor.
- **Each setting saves as you change it.** There's no Save button: a switch or menu saves straight away, and a box saves when you press Enter or leave it. A change speck refuses goes back and says why. So nothing is lost by closing Settings, and a bad value is caught on the spot.
- **Try it from the review pack.** An approved ticket's review pack has a Try it button that starts the app from that ticket's code and gives you its address, with Stop beside it. So you can try a change in the real app before you ship it.
- **A machine-wide build limit.** `speck config set machine_parallel_builds <n>` caps the builds running at once across every project on this machine, and Settings now shows the matching test-run limit too. So several projects running `speck run` don't swamp one computer.
- **A usage warning on the bridge.** All projects shows a line when an agent is at 90% or more of a usage window, or limited, naming the window and when it resets. Claude's reading is also refreshed after a Claude review round. So you see a limit coming before builds stop on it.
- **Sonnet means Sonnet.** Choosing Sonnet for the builder, the reviewer or a level now saves `sonnet`, and "Claude Code · its own default" is a separate choice. So a build runs on the model you picked, not whatever Claude Code would choose.
- **Chains that light softly.** Hovering a ticket lights it and its chain with a soft fill rather than a dark ring, and closed drafts in Plan leave Set ready to the open card. So the lanes are calmer and titles have more room.
- **Tickets built on others stall less.** A ticket built on an unshipped ticket waits under Building rather than asking for you, and when the ticket it was built on is cancelled, speck gives two ways on instead of asking you to ship a cancelled ticket. A handed-back build that hits a usage limit carries on on the next free agent on `builder_bench`. So the queue keeps moving without you untangling it.
- **Checks in the app say who's on them.** While speck is checking a question in the running app, the ticket says so instead of "Waiting for you", and the watching agent knows when to leave a sign-in check for you. So Needs you holds only what really needs you.

There are smaller fixes too: Shipped's figures keep their labels whole, build timers count smoothly, the Pipeline log reads in whole sentences, the panel is stronger with your device's more-contrast setting, `speck set` can blank a ticket's level or builder, and `speck logins set` warns about a weak test password. Several of speck's own tests that failed now and then on a busy machine are steady, and a ship now refuses rather than carrying on if the main checkout has lost its working files. The shipped price table has this release's rates. Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v1.6.0 init
```

## Upgrading from 1.5.0

- Run `npx github:luroai/speck#v1.6.0 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- Settings saves each change as soon as you make it, and there's no Save button. Each project setting you change is its own commit to `speck/config.yml`, so changing several makes several small commits.
- Swapping the builder and the reviewer between Claude Code and Codex now takes a step through a third choice, as each half of the swap is refused on its own while both are the same agent.
- A new home-folder setting, `machine_parallel_builds`, caps builds across every project on this machine. Set it with `speck config set machine_parallel_builds <n>`. Unset, each project's `max_parallel_builds` applies alone, as before. Nothing in `speck/config.yml` changes.
- A builder, reviewer or level saved with no Claude model now reads "Claude Code · its own default" rather than Sonnet. If you meant Sonnet, choose Sonnet again, which saves `sonnet`.
- Set ready is no longer on a closed draft's row in Plan: open the draft to set it ready.

See everything that's changed in the [1.6.0 section of the changelog](https://github.com/luroai/speck/blob/v1.6.0/CHANGELOG.md#160--24-november-2026).
