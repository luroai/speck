0.7.0 is a minor release that lets you build your tickets with Codex or Cursor as well as Claude Code, have Claude Code review whichever agent builds them, and choose from the agents and models really on your machine.

## What matters most

- **Build with Codex.** Set `builder: codex` and `build_command: ""`, and `speck run` starts each build with Codex, on the model in `builder_model` if you set one. When a build is stopped or a ship hands a ticket back, it carries on in that build's own Codex session, as Claude Code builds already did, so the work and its context aren't lost.
- **Build with Cursor.** Set `builder: cursor` and `build_command: ""`, and `speck run` opens a Cursor chat for each build and runs it there, on `builder_model` or, when that's blank, on Cursor's Auto model, which is the one a free Cursor plan allows. Stopped and handed-back builds carry on in the same chat. If Cursor can't open a chat, `speck run` says why and tries again shortly after, leaving the ticket ready.
- **Follow every build in the panel.** A Codex or Cursor build's live log reads like a Claude Code one, with the agent's messages and one line per command, and its tokens are counted with the rest. Neither agent reports a cost, so none is shown rather than a misleading $0.
- **Switch the builder without editing files.** Pick the builder in the panel's Settings view, or run `speck config set builder <name>`, and speck sets `build_command` to match, so there's nothing to write by hand. Setup does the same, recommending Claude Code. The Settings view asks before replacing a `build_command` you wrote yourself, and refuses a builder from the reviewer's own family, suggesting another reviewer instead, unless you allow same-model review or both are Claude on two different models you've chosen.
- **Claude Code as the reviewer, whatever builds.** `reviewer: claude` runs Claude Code itself for each review round, read-only, so a Codex or Cursor build gets an independent review from another family of models. Later rounds carry on the same conversation, and `reviewer_model` and `reviewer_effort` are used when set.
- **Only what's really there.** The new `speck agents` command says which of Claude Code, Codex and Cursor are installed and signed in on this machine, and lists their models with proper names and descriptions. The Settings view and setup use it, so they offer only reviewers that can run and show each model's name and description instead of a raw id.

## Install

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.7.0 init
```

## Upgrading from 0.6.0

- Run `npx github:luroai/speck#v0.7.0 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- Nothing changes unless you choose it: there are no new settings in `speck/config.yml`, and Claude Code builds and Codex reviews work as before. A `build_command` you've set is still used as it is.
- To build with Codex or Cursor, switch the builder in the Settings view or with `speck config set builder codex` (or `cursor`), which leaves `build_command` blank so speck uses that agent's own command. A Codex builder with the default Codex reviewer is refused, as the two are the same family, unless you set `allow_same_model_review: true`: `reviewer: claude` is the new choice from another family.
- `builder_model` is now passed to the Codex and Cursor builds speck starts with their own command, as well as to Claude Code ones. Switching the builder keeps it as it was, so check it still names a model the new builder has.
- Switching the builder doesn't change tickets already made, but `speck run` builds every ready ticket with the builder in `speck/config.yml`, including older ones.
- A `speck run` that's already on is still running its old code until it switches by itself once it's idle.

See everything that's changed in the [0.7.0 section of the changelog](https://github.com/luroai/speck/blob/v0.7.0/CHANGELOG.md#070--18-october-2026).
