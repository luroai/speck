1.5.0 is a minor release that finishes "picks the crew" with a sweep for reliability. Since 1.3 you could build a ticket at a level, but you had to pick one yourself, and nothing showed whether a cheaper model held up. Now the ticket writer suggests a level for each ticket, and Shipped compares builder models by their results. The line also gets stuck less: review rounds carry on through more usage limits, and a cancelled ticket or a fix ticket no longer leaves work waiting.

## What's new

- **A suggested level for each ticket.** `/speck-ticket` sets a level on each ticket it writes when one of your levels fits the work better than the settings, such as a cheaper one for a wording change or a deeper one for a risky change, and gives a one-line reason. You can change it before you set the ticket ready, and setting a level never sets a ticket ready. So the right model builds each ticket without you remembering to pick it.
- **Builder models compared in Shipped.** A By model table under Shipped's figures gives each builder model's tickets, time, review rounds, first-round approvals and cost, marking a model with fewer than 5 tickets. A shipped ticket's full view says which model built it. So you can see whether a cheaper model holds up or only looks cheaper.
- **Usage limits on the reviewer stay on record.** Once a stand-in from `reviewer_bench` has taken a round for a limited reviewer, later rounds go straight to the stand-in until the limit resets, and the status keeps saying when that is. So rounds don't start by asking a reviewer that's sure to refuse.
- **The next agent on the bench.** When the stand-in is limited too, the round goes to the next free agent on `reviewer_bench`, and the build waits only when none can take it, carrying on after the first reset. So one limited stand-in doesn't stop a build while another agent is free.
- **Handed-back builds carry on after a limit.** A build that `speck run` handed back, for example to settle a clash at ship, is carried on after a usage limit resets, without spending another hand-back. So an approved ticket doesn't sit for days while you're away.
- **A ticket cancelled during its build no longer holds others up.** speck run records the cancel on the base branch too, and tickets with it in `after:` say it was cancelled instead of waiting for it. So a cancel can't stall the queue unseen.
- **Fix tickets may fix their tests.** A `type: fix` ticket may change or fix the failing tests it names, while every other test that failed before its build stays off limits. So the reviewer stops escalating fix tickets for doing their job.
- **Panel breakages show up before review.** `speck test --related` brings in the tests that load the panel when a build changes a file the panel's page loads. So a panel change that breaks them is caught before review rather than at ship.

Several of speck's own tests that failed now and then on a busy machine are steady. The shipped price table has this release's rates. Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v1.5.0 init
```

## Upgrading from 1.4.0

- Run `npx github:luroai/speck#v1.5.0 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- There are no new settings in `speck/config.yml`.
- `/speck-ticket` now sets `level` on the tickets it writes when one of your levels fits. A ticket with a level builds with that level's builder, model and effort rather than the settings, so read the suggestion before you set the ticket ready, and change it or clear it if it doesn't suit.
- With two or more agents on `reviewer_bench`, a round may now run on the second or a later one when the reviewer and the first stand-in are both limited.
- A `type: fix` ticket's build and review may now change the failing tests it names.
- A ticket cancelled during its build is now cancelled on the base branch too. Take it out of the `after:` lists that name it, as speck run says.
- `speck test --related` runs take longer after a change to the panel's files, as they now include the tests that load the panel.

See everything that's changed in the [1.5.0 section of the changelog](https://github.com/luroai/speck/blob/v1.5.0/CHANGELOG.md#150--15-november-2026).
