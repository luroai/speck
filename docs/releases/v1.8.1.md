1.8.1 is a patch release that makes `speck serve` easier to live with and fixes a few rough edges found the day 1.8.0 came out. When 1.8.0 shipped, its factory floor stayed missing until `speck serve` was restarted by hand, and every update would have needed the same. Stopping an installed `speck serve` didn't hold, as the service started it again. This release fixes both, gets test summaries working again on Node 24, keeps a build's related test run small when a page changes, and says when a ticket is waiting on approved work.

## What's new

- **`speck serve` switches to new code by itself.** When the code it runs from changes, for example when you update speck in that project, it moves to the new code within a few seconds, keeping its address answering and the project panels it started running. If the new code can't start, it carries on with the old and says why in its log. So a new release reaches All projects and the factory floor without a restart.
- **`speck serve --stop` stops the installed service.** With the service `speck serve --install` makes, `--stop` now stops the service itself, so `speck serve` stays stopped rather than coming back a few seconds later, and it says how to start it again. The service stays installed and starts again at the next boot. So stopping it does what it says.
- **Test summaries on Node 24.** speck reads the new layout `node --test` prints by default on Node 24 as well as the old one. So a failing run again ends with the command to run only the failing files, and the reviewer gets a short summary rather than the whole output.
- **Smaller related test runs.** `speck test --related` brings in a test support module's tests only for files its code names, not ones its comments mention. So a change to one page runs the handful of tests that load it rather than hundreds, and a build's related run fits inside its agent's command limit.
- **Waiting on approved work says approved.** A ticket's Waits for fact shows a ticket it waits on as approved when it's approved and waiting to ship, rather than building. So you know to chase the shipping rather than the build.

Several of speck's own tests are steady on a busy machine, so fewer finished tickets are sent back because one of them failed. The shipped price table has this release's rates. Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v1.8.1 init
```

## Upgrading from 1.8.0

- Run `npx github:luroai/speck#v1.8.1 init` again in each project to update the speck command and skills. It keeps your config and tickets, and nothing in `speck/config.yml` changes.
- A `speck serve` that was running before this release doesn't switch to new code by itself yet, so restart it once after updating the project it runs from: `speck serve --stop`, then `speck serve --background`. If you installed it with `speck serve --install`, run `speck serve --install` again from the updated project, with the same `--port` and `--url`: it replaces the service and starts it on 1.8.1. From then on, updates reach it by themselves.
- After its first switch to new code, `speck serve` shows as two processes: the one you started, which stays so that `speck serve --stop` and the service still find it, and the one running the new code. That's expected.

See everything that's changed in the [1.8.1 section of the changelog](https://github.com/luroai/speck/blob/v1.8.1/CHANGELOG.md#181--27-november-2026).
