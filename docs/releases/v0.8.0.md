0.8.0 is a minor release that gives speck a Foreman, one status for the whole pipeline that can also clear technical blockages by itself, shows pictures of a visual change in its review pack before you ship it, and can ship through GitHub pull requests.

## What matters most

- **One status for the whole pipeline.** The button at the top of the panel is now the Foreman: Off, Idle, Building, Shipping, Waiting with its reason, or Needs you. Press it to see why each ready ticket isn't building, what each approved ticket is waiting for before it ships, and each blocked ticket's question. `speck status` gives the same. You no longer have to dig through `speck run`'s log, or ask an agent, to find out why nothing is moving.
- **Blocked questions say what's at stake.** A build that stops to ask you something now says which option it recommends, whether any option would change something you'd notice, and whether its pick is a clear winner or a close call. The panel shows this under the question, with a "Go with the recommendation" button that carries the build on with it, so taking the recommendation no longer means resuming a session by hand.
- **Technical questions answered for you, if you want.** With `foreman_fixing: fix`, `speck run` takes the recommendation itself when no option changes anything you'd notice and it's a clear winner, once per ticket, and notes that in the ticket. Everything else still waits for you.
- **Stops speck has no steps for get looked into.** With `foreman_fixing: fix`, when a ship is refused for an unusual reason or a build ends without its ticket approved or blocked, a Foreman agent looks into it and does one thing: carries the build on, tries the ship once more, writes a draft fix ticket or asks you one question. It never sets a ticket ready, approves work, ships anything `auto_ship` doesn't cover or changes code, and what it did is in the ticket's Notes.
- **See a visual change before you ship it.** When a ticket changes how something looks, the build takes pictures of the result in a real browser, in light and dark, and the review pack shows them. You can judge the change without reading code or checking out the branch. The pictures stay on your computer and are never committed.
- **Ship through pull requests.** With `ship_mode: pr`, an approved ticket gets a GitHub pull request with its review pack, and shipping it merges that pull request once its checks pass, then tidies up. Merge it on GitHub yourself and speck only tidies up. Teams that ship through pull requests can now use speck. On a main branch that only takes pull requests, the ticket's "done" commit can't be pushed, and the panel says so.
- **Every build counted, and new code without the wait.** `speck run` now sees builds you start with `/speck-build` in a conversation or carry on by hand, and counts, shows and watches them as its own. When a shipped ticket changes speck itself, `speck run` switches to the new code as soon as no ship is running, so approved tickets no longer wait for unrelated builds to finish before they ship.

## Install

Paste the setup prompt from the README into your coding agent, or run this in your project's folder:

```sh
npx github:luroai/speck#v0.8.0 init
```

## Upgrading from 0.7.0

- Run `npx github:luroai/speck#v0.8.0 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- The panel's header button no longer turns `speck run` on or off: that switch is now the first thing in the Settings view, in the Foreman group.
- New settings, each with a default that keeps speck working as before. You don't need to add them to `speck/config.yml`:
  - `foreman_fixing`: `off`, `tell` or `fix`, `tell` by default. `tell` leaves every blocked question for you, as before. Only `fix` answers questions or starts the Foreman agent.
  - `foreman`, `foreman_model` and `foreman_effort`: the agent the Foreman agent runs on (`claude` or `codex`), its model and its effort. Blank, the default, uses the builder when that's Codex, and Claude Code otherwise, on that agent's own model and effort.
  - `ship_mode`: `local` or `pr`, `local` by default, which ships as before. `pr` needs GitHub's `gh` command, installed and signed in.
- A `speck run` that's already on keeps its old code until it switches by itself. The Foreman's reasons show once it's running 0.8.0; until then the status shows Idle.

See everything that's changed in the [0.8.0 section of the changelog](https://github.com/luroai/speck/blob/v0.8.0/CHANGELOG.md#080--18-october-2026).
