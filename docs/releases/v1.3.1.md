1.3.1 is a bug-fix release that makes 1.3.0's build levels easier to use. In 1.3.0 a level's model was a free-text box, "settings" appeared everywhere without saying what it meant, and a ticket's Level menu didn't say what each level builds with. Now levels are set with the same labelled lists as the Builder itself, the Level menu says what each choice builds with, and a ticket in the panel shows, and lets you change, the builder and model it will be built with.

## What's fixed

- **Levels set from lists.** On the Builder's card, each build level now has a Builder list with the same choices as the Builder's own row, such as "Claude Code · Opus", and an Effort list with the efforts that model offers. "Default" comes first in each and names what the Builder uses now. So you pick a level's model rather than typing its name, and can't mistype it.
- **A tidier Build levels.** Every list and box is labelled, the line repeating each level's values is gone, Remove is a small text button, and it fits a phone's width without scrolling sideways. So the card reads at a glance.
- **A Level menu that says what it does.** Under each level, a ticket's Level menu shows the builder, model and effort it builds with. The choice that takes the level off is now "Default", not "Settings", and the menu ends with "Change levels", which opens Settings at Build levels. So you can see what you're choosing, and where to change it.
- **A ticket's builder in the panel.** A ticket's facts now show a Builder fact: the agent, model and effort its next build will use, and whether that comes from the ticket, its level or the default. Press it to pick another agent and model, or "Default" to hand it back. So you can check and change what a ticket is built with from your phone, without editing the ticket file.
- **Steadier tests.** Several of speck's own tests that failed on `main` when the machine was very busy, and one that went stale once its fixed date passed, now pass reliably. Nothing changes in speck itself.

Costs speck works out from tokens are still estimates at API list prices, so they can differ a little from what you were billed.

## Update

Paste the setup prompt from the README into your coding agent, or run this in each project's folder:

```sh
npx github:luroai/speck#v1.3.1 init
```

## Upgrading from 1.3.0

- Run `npx github:luroai/speck#v1.3.1 init` again in each project to update the speck command and skills. It keeps your config and tickets.
- There are no new settings, so nothing needs adding to `speck/config.yml`, and the Builder's card saves the same values there as in 1.3.0.
- Picking a ticket's builder in the panel sets its `builder` and `builder_model` lines, as `speck set` does. "Default" blanks both. A ticket that's building, reviewing, blocked or waiting to ship refuses the change.
- A ticket with no level now shows "Default" as its Level, where 1.3.0 showed "Settings". It builds exactly as before.

See everything that's changed in the [1.3.1 section of the changelog](https://github.com/luroai/speck/blob/v1.3.1/CHANGELOG.md#131--15-november-2026).
